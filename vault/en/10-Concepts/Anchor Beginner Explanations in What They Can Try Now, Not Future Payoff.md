## Summary

For first- and second-year students, "you'll use this after graduation or in senior courses" and lecture-style syntax walkthroughs did not land — **lay down what they can try during the course right now, tools they already use and one everyday analogy carried all the way through, then put the terminology on top.**

## Details

- User correction 1: each course's "where is this used" pointed only to post-graduation jobs or later courses, which is abstract to students who have not taken those courses. Every course got a "what you can do now, while learning it" item — the ArrayList, HashMap and Stack they already use are data structures; export phone health-app data and chart it in Excel; run the tests learned in class on a public health-checkup sample CSV; use free student editions of analysis tools.
- User correction 2: the Java part leaned toward lecture-style syntax, while the goal was thinking in objects. A single car-factory analogy ran through five slides — one craftsman vs a factory with divided labor → blueprint and car → different models on the same chassis → a repair shop that "takes any car" → an analogy ↔ term ↔ one-line-of-code table. Code appears only in that final table.
- Carry the analogy into the exercise: the exercise opens with a "factory ↔ game" mapping, so the talk's analogy carries straight over to the code structure (blueprint = class, chassis = parent class).
- Keep practical needs, but stack them on the analogy: exam topics went into the table too — overloading as "the same car-wash button with different options," private as "only mechanics open the engine bay."
- Drop motivators that do not match the audience's reality: "coding-test prep" was used as a motivator until the user corrected it ("coding tests are fading in industry; they won't relate"). It was replaced with "a standard for judging whether AI-written code is correct and why it is slow" plus a code-execution visualizer — an LLM's default motivators can be the conventional wisdom of its training period.
- Weight topics by what the audience finds hard, not by the session's headline: the three foundational CS courses students struggle with most had been squeezed into one slide; they became their own section (why it is hard → why it matters → how the three connect → what to do now).
