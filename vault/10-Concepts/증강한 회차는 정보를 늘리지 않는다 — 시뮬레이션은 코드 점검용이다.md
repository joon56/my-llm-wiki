## 한 줄 요약

실측 한두 번에서 뽑아낸 시뮬레이션 회차는 **표본 수만 늘릴 뿐 정보량은 그대로**라 가설의 근거가 될 수 없다 — 시뮬레이션은 분석 코드 점검과 그림 미리보기에 쓰고, 판정에 필요한 값은 실측과 잡음 추정에서 직접 계산한다.

## 내용

- 흔한 생성 방식: 같은 조건의 실측 센서 기록에서 시간축만 s배 늘이거나 줄여 부족한 회차를 채운다. 케이던스·속도는 1/s배가 되지만 걸음 수, 경로, 신호 모양은 원본 그대로다. s는 실측값 중심의 로그 정규로 뽑았고, 퍼짐 σ(1.7%)는 같은 조건을 두 번 잰 한 쌍에서만 추정했다.
- 정보는 늘지 않는다: 시뮬 회차는 실측 패턴의 복제라 15회로 보여도 정보량은 실측 1~2회 그대로다. 증강 데이터에서 보이는 경향은 이미 실측에 있던 것이고, 실측에 없던 경향이 나타났다면 난수의 산물이다.
- 숫자가 난수에 좌우된다: 시뮬로 채운 기준선 회차가 우연히 느리게 나오면 기준선이 내려가고, 그 기준선으로 계산한 모든 조건의 효과가 함께 움직인다. 시드를 바꾸면 결론이 뒤집히는 수치는 증거가 아니다.
- 분산이 과소평가된다: 걸음 하나하나의 모양(멈춤, 방향 전환, 걸음 사이 변동)이 원본의 복사라 변동성 지표가 실제 재측정보다 원본과 훨씬 비슷하게 나온다. 반복 측정이었다면 있었을 흔들림이 빠져 실제보다 정밀해 보인다.
- 제대로 된 쓰임은 코드 점검이다: 시뮬 파일 19개가 프로젝트의 읽기 코드로 모두 열리는지, 샘플 간격이 원본과 같은지, 회차별 케이던스가 목표값과 맞는지, 가속도에서 잰 걸음 주파수도 1/s만큼 바뀌었는지(변환이 메타데이터가 아니라 신호에 적용됐는지)를 확인하는 데 쓴다.
- 판정 질문은 실측에서 계산한다: 회차 간 잡음 σ와 조건당 회차 n이 있으면 "우연과 구분되는 최소 평균 차이"는 대략 2σ√(2/n)이다(σ = 1.7 걸음/분, n = 3이면 약 2.8 걸음/분). 분석 코드가 판정을 제대로 내리는지 보려면 실측과 무관한 합성 데이터에 정답을 심은 테스트 세트를 따로 만든다.
- 격리하고 표시한다: 파일명에 `sim-` 접두어를 붙이고, 메타데이터의 기기 이름·ID 칸(파이프라인이 쓰지 않는 칸)에 `SIMULATED`를 넣고, 실측과 다른 폴더에 둔다. 원자료와 형식이 같아서 섞이면 구분할 방법이 없다. 생성 파라미터를 기대하는 결론 쪽으로 조정하는 순간 시뮬레이션은 점검 도구가 아니라 조작 데이터가 된다.
