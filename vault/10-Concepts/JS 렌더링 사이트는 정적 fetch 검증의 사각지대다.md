## 한 줄 요약

정적 fetch(HTML만 받아 텍스트 추출)로 공식 사이트를 검증하면 **JS 렌더링 사이트에서 "정보 없음"과 "정보 있음(못 읽음)"을 구분하지 못한다** — 빈 결과를 "일정 미공개"로 단정하면 틀린다.

## 내용

- 실제 사례: 한 대회 공홈을 이틀에 걸쳐 fetch — 제목 한 줄만 나와서 "일정 미게시"로 기록. 실제로는 접수 기간·예선·본선·연장 공지까지 전부 있었고, **JS 번들 안의 텍스트**로 존재했다.
- 정적 fetch가 빈약한 결과를 줄 때의 판별 절차:
  1. "없다"가 아니라 "**못 읽었다**"로 기록한다 (unverified ≠ unannounced).
  2. **JS 번들을 직접 fetch**해 본다 — SPA의 공지 문자열·카운트다운 타깃(`2026-08-18T18:00:00+09:00` 같은 ISO 날짜)이 번들에 하드코딩된 경우가 많다.
  3. 같은 내용을 전재한 2차 출처를 찾는다 — 대학 공지사항, 링커리어/위비티 공고문, 보도자료가 공식 공고를 그대로 옮겨 싣는 경우가 많다.
  4. API 엔드포인트를 추측해 본다 — 티켓/등록 시스템은 별도 REST API(`orderable_ends_at` 등)로 마감 정보를 노출하기도 한다.
- 이 함정은 자동화 링크 체커에도 적용된다: HTTP 200 + 빈 본문은 "살아있는 사이트"이자 "읽을 수 없는 사이트"다. urllib 수준의 체커가 내는 URLError/403은 죽은 링크가 아니라 봇 차단인 경우가 대부분이므로, 경고를 죽은 링크로 단정하기 전에 브라우저급 fetch로 재확인한다.
