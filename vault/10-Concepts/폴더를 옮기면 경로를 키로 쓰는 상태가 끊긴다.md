## 한 줄 요약

프로젝트·도구 폴더를 다른 드라이브로 옮기면 venv, 하드코딩 경로, 에이전트 세션 기록처럼 **경로를 키로 쓰는 상태가 조용히 끊긴다.** 먼저 그것들을 목록화하고, 복사 → 대조 → 전환 → 동작 확인 → 원본 삭제(make-before-break) 순서로 옮긴다.

## 내용

- 이전 전에 조사할 '경로를 키로 쓰는 상태': Python venv(절대경로가 박혀 있어 옮기면 실행되지 않으니 새 위치에서 다시 만든다), 스크립트·노트북·docker·IDE 설정의 하드코딩 경로(`C:\Users\<사용자>` 문자열을 grep), IDE·도구 설정에 적힌 SDK 경로, 메모리 본문에 적힌 절대경로.
- 에이전트 기록도 경로에 묶인다: Claude Code의 세션 기록과 메모리는 `~/.claude/projects/<인코딩된 경로>` 아래에 있어서, 폴더를 옮기면 새 프로젝트로 인식돼 메모리와 `--resume` 기록이 보이지 않는다. 옛 디렉터리를 새 경로 이름으로 복사해 잇는다.
- 파일 잠금: IDE, Gradle 데몬, adb, node, 에이전트를 먼저 끈다 — 실제로 놀고 있던 Gradle 데몬과 adb 서버가 SDK 파일을 잡고 있었다. 지금 세션이 쓰는 폴더는 세션 중에 옮길 수 없다.
- 순서(make-before-break): 복사 → 파일 수·바이트 대조 → 설정 전환(전환 전 설정 파일 백업) → 새 위치에서 동작 확인 → 원본 삭제(직전에 한 번 더 확인). 검증이 끝나기 전에는 원본을 지우지 않는다.
- 실제 SDK 이전: robocopy 뒤 파일 수 39,820개·19,785개 일치를 확인했다(robocopy 종료 코드 1은 '복사됨'이라 실패가 아니다). IDE 설정 파일 2개를 고치고 사용자 환경변수를 건 뒤, 새 위치의 SDK가 패키지 8개를 인식하는지 보고 나서야 C: 원본을 지웠다(3.2GB 확보). IDE·에디터는 재시작해야 새 환경변수를 읽는다.
- 권한 이전도 같은 원칙이다: 클라우드 프로젝트 소유권을 넘길 때 '옛 계정을 지우기 전에 새 소유자의 실제 접근부터 확인'을 순서로 못 박았다. CLI 로그인, DB 조회, 보안 규칙 배포 dry-run, IAM 역할을 확인한 뒤 앱 로그인 회귀까지 봤다.
- 환경 조건: 대상 경로는 ASCII로 한다(한글 경로는 Android 빌드 도구 AAPT2에서 문제를 일으킨다). 여유 공간이 0에 가까우면 이전 전에 Temp부터 비운다 — 복사본은 다른 드라이브에 써도 에디터와 에이전트는 계속 C:에 쓰므로 도중에 쓰기가 실패할 수 있다.
