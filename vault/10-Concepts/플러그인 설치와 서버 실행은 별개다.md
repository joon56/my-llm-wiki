## 한 줄 요약

외부 데몬에 의존하는 플러그인은 **설치해도 데몬이 따로 존재하고 실행 중이어야 작동**한다 — 플러그인은 훅과 연결부만 등록할 뿐, 서버를 같이 띄워주지 않는다.

## 내용

- agentmemory 사례: Claude Code 플러그인이 하는 일은 훅 등록 + MCP stdio 연결부(shim) 제공까지다. 실제 저장은 별도 데몬(iii 엔진, REST 포트 3111, 뷰어 포트 3113)이 담당하며, 이 데몬은 별도로 존재하고 실행돼 있어야 한다.
- "플러그인 설치했는데 왜 데이터가 없지?"의 정답은 대부분 **데몬 부재**다 — 이 사례에서는 iii-engine 바이너리 자체가 없었고, GitHub releases에서 수동 다운로드해서 해결했다.
- 사용 모델은 3계층이다: (1) 수동 슬래시 스킬 `/remember` `/recall` `/handoff`, (2) 에이전트가 스스로 호출하는 MCP 툴, (3) 세션 이벤트를 자동 수집하는 훅. 세 계층 모두 밑에서 같은 데몬을 바라본다.
- 그래서 데몬이 죽으면 세 계층이 동시에 조용히 무력화된다 — 어느 층에서도 명시적 에러가 안 나는 경우가 많다.
- 진단 순서: 플러그인 설정을 의심하기 전에 먼저 데몬 프로세스와 포트(3111)가 살아 있는지 확인하라. 설치 여부와 실행 여부는 항상 별개의 질문이다.
