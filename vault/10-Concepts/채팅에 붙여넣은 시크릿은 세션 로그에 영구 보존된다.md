## 한 줄 요약

Claude Code는 모든 메시지를 로컬 JSONL 트랜스크립트에 기록하므로, 채팅에 붙여넣은 GitHub PAT 같은 시크릿은 평문으로 무기한 남는다 — 채팅 입력은 한 번 쓰면 지울 수 없는 저장소로 취급해야 한다.

## 내용

- Claude Code는 세션의 모든 메시지를 로컬 JSONL 트랜스크립트 파일에 기록한다. 채팅창에 붙여넣은 토큰은 그 파일에 평문으로 영구 보존된다 — 이번 세션에서 실제로 확인한 사실.
- 세션이 끝나도 로그는 사라지지 않는다. 로그를 아카이브·정제하는 파이프라인(이 위키처럼)이 있으면 시크릿이 다른 저장소로 전파될 수도 있다.
- 실제 사용한 완화책 1: 토큰을 처음부터 **짧은 만료 기간(7일)**으로 발급해, 유출되더라도 피해 창을 줄인다.
- 실제 사용한 완화책 2: 작업이 끝나면 **즉시 revoke**한다. 로그에 남은 토큰은 못 지워도, 죽은 토큰으로 만들 수는 있다.
- 실제 사용한 완화책 3: push 직후 `.git/config`의 remote URL에서 토큰을 제거한다. remote URL에 박힌 토큰도 설정 파일에 평문으로 남는 저장 지점이다.
- 일반 원칙: 시크릿은 채팅에 붙여넣지 말고 환경 변수나 credential helper로 전달한다. 붙여넣는 순간 "삭제 불가능한 곳에 기록됐다"고 가정하고 만료·폐기 계획을 세워야 한다.
- 보충(2026-11-21): 원본 트랜스크립트 자체는 영구가 아니다. Claude Code는 시작할 때 마지막 활동이 `cleanupPeriodDays`(기본 30일)보다 오래된 JSONL을 지운다. 그래도 규칙은 그대로다 — 그 전에 아카이브 노트, 메모리 임포트, 백업으로 사본이 퍼지고 어디까지 갔는지 추적하기 어려우므로, 붙여넣은 시크릿은 계속 영구 기록으로 취급한다.
- 값을 채팅에 싣지 않는 전달 경로: 에이전트가 저장소 밖(또는 git 제외 폴더)에 빈 양식 파일(`secrets.env` 등)을 만들고, 사용자가 메모장으로 직접 값을 넣은 뒤 "저장했어"만 알린다. 스크립트는 파일에서 읽기만 하고, 확인은 값 대신 통과·실패, 접두사·길이, 행 수만 출력한다. 비밀번호가 찍힐 수 있는 명령(터널 기동 등)은 출력을 파일로 보내 필요한 줄만 읽고, 좌표 같은 위치 정보도 같은 등급으로 다룬다.
- 타이핑 말고도 새는 경로가 있다: 스크린샷도 붙여넣기다 — 자격 증명 화면 캡처가 대화에 남았을 때는 그 값을 쓰지 않고 서비스에서 새로 발급받은 값만 썼다. IDE 연동은 선택해 둔 텍스트와 열린 파일 정보를 다음 메시지에 자동으로 붙이므로, 민감 파일을 다룬 뒤에는 선택을 풀고 파일을 닫은 다음 대화한다. 웹 콘솔 SQL 편집기의 쿼리 탭·저장 스니펫에도 키가 남으므로 실행 뒤 지운다.
