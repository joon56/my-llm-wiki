## 한 줄 요약

오프라인 데이터 생성 경로(vLLM 등)와 평가 런타임(HF transformers 등)은 **토크나이저·샘플링 기본값·옵션 커널 패키지·패딩·예산 단위에서 에러 없이 어긋난다** — 항목별 사양 대조와 라운드트립 검사로 학습 데이터가 오염되기 전에 맞춘다.

## 내용

- 계기: 사용자가 "모델 사양도 중요하지 않냐"고 묻자 체크포인트 해시·정밀도·컨텍스트 길이·샘플링 설정을 평가 환경과 항목별로 대조했다. 그 과정에서 이미 돌고 있던 생성 작업 하나가 오염된 입력을 먹고 있음을 발견했다.
- 토크나이저: transformers 5.x의 기본 로더가 DeepSeek-R1 계열 증류 모델의 띄어쓰기를 전부 지웠다(평가 쪽 버전과 생성 쪽 버전 모두). 제출 코드의 공용 로더에는 encode→decode 라운드트립 검사가 있었지만 별도 데이터 생성 스크립트에는 없었다 — 알려진 함정의 방어가 한 경로에만 있었다. 검증된 토크나이저로 만든 token id 프롬프트를 vLLM에 넘기도록 고쳐 약 10분 손실로 막았다.
- 우회책은 해당 모델에만 건다: 토크나이저 초기화 생략을 전역으로 걸자, 멀티모달 처리기 때문에 토크나이저가 꼭 필요한 다른 모델(Qwen3.5)의 생성이 실패했다. 모델별 예외로 좁혀 해결했다.
- 샘플링 기본값: 라벨은 T=1.0·top_k 40·top_p 0.95로 만들어졌는데, 한 모델(Olmo)의 기본 generation config는 T=0.6이었다. 기본값에 맡기면 에러 없이 다른 분포에서 샘플링하므로 라벨 생성 설정을 명시적으로 고정했다.
- 옵션 패키지: `kernels` 패키지가 없으면 transformers가 gpt-oss의 MXFP4 가중치를 풀어 올리다 OOM이 났고, 설치해도 인정 버전대(0.15.x) 밖이면 무시돼 다시 OOM이 났다. 평가 환경 Docker 이미지 태그에 적힌 버전으로 맞추자 압축 형식 그대로 로드됐다.
- 패딩: hidden state를 배치로 추출할 때 left padding은 토큰 위치와 선형 어텐션의 순차 상태를 바꿔 값을 오염시킨다. 접두 길이가 같은 '한 문제의 샘플들'끼리만 패딩 없이 묶었다.
- 피처 정의도 같은 조건으로: 토큰 상한은 artifact에 저장해 학습과 추론이 같은 값을 읽게 하고, 긴 학습 풀이는 배포 상한으로 다시 잘라(re-censoring) 피처를 계산했다. 배포 상한에서 재현할 수 없는 피처(강제 답변 일치도)는 모델 선택 후보에서 뺐다.
- 원칙: 평가 환경의 버전·기본값·옵션 의존성을 목록으로 만들어 생성 경로와 한 줄씩 대조하고, 텍스트가 지나가는 경로마다 라운드트립 검사를 둔다. 이런 불일치는 에러 없이 학습 데이터만 조용히 바꾼다.
