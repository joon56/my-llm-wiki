## 한 줄 요약

"에러 없이 실행된" 차트 코드도 시각적으로는 깨져 있을 수 있다 — matplotlib이 PNG를 만들면 에이전트가 그 이미지를 직접 Read로 읽어 눈으로 검토하고 고치는 루프를 돌려야 한다.

## 내용

- 루프: matplotlib으로 PNG 렌더 → 에이전트가 결과 이미지를 Read(이미지 읽기) → 텍스트 겹침 등 결함 발견 → 코드 수정 → 재렌더. 관찰된 세션에서는 2회 반복으로 수렴.
- 발견된 결함 유형: 라벨/텍스트 겹침 — 코드 실행 성공 여부만으로는 절대 잡히지 않는 문제.
- 원칙: "에러 없이 돌아간다"는 코드 정합성 검증일 뿐, 산출물이 이미지라면 검증도 이미지 수준에서 해야 한다.
- 보너스 패턴 — GitHub README의 다크/라이트 테마 대응: 라이트용·다크용 PNG를 한 쌍으로 렌더하고, README에서 `<picture>` + `prefers-color-scheme` 미디어 쿼리로 분기 참조한다.
- 이 패턴은 차트에 국한되지 않는다: 다이어그램, 스크린샷 합성 등 시각 산출물 전반에 같은 read-back 검토가 적용된다.
- 실패한 재생성은 옛 그림을 남긴다: 콘솔 화면 캡처 스크립트가 창 폭(100칸) 조정에 실패했는데 오류 없이 옛 그림이 그대로 남아 '갱신 완료'처럼 보였다. 생성물은 파일이 있는지가 아니라 그림 내용이 바뀌었는지까지 열어서 확인한다.
- 생성한 PDF 보고서도 쪽 이미지로 렌더해 검토한다: 캡션 글자 겹침, 표 아래 선이 테두리까지 이어짐, 표·그림 제목이 쪽 사이에서 갈라짐, 쪽 끝에 홀로 남은 소제목이 나왔다. python-docx에서 행 분할 금지(`cantSplit`)와 한 칸짜리 표로 묶기로 고쳤다(표 칸 안에서는 쪽 나누기 설정이 듣지 않았다).
- README도 렌더해서 본다: GitHub 렌더러로 미리보기를 만들어 이미지로 확인하자 한국어 표 첫 열이 글자 단위로 세로로 꺾이는 결함이 보였다(문법 검사로는 안 잡힘). 첫 열 머리칸에 보이지 않는 고정폭 공백을 넣어 폭을 확보했고, 알림 상자·`<details>`·Mermaid·배너 SVG도 같은 방식으로 확인했다.
