## 한 줄 요약

섹션마다 승인을 기다리는 에이전트는 오히려 교정을 받는다. **되돌리기 어렵거나 선호가 갈리는 결정만 추천안을 붙인 선택지로 한 번에 묻고, 나머지는 가정 목록을 공개한 채 끝까지 진행하며, 푸시·공개·기능 제거만 자율 범위 밖에 둔다.**

## 내용

- 교정 1: 설계안을 올리고 환경 준비를 끝낸 뒤에도 '피드백 기다리는 중'을 두 번 반복하자, 사용자가 "내 피드백을 기다리는거야? 일단 전부 진행해."라고 했다. 이후로는 질문 없이 끝까지 진행하고 결정 사항은 결과 보고에 적었으며, 이 선호를 피드백 메모리로 남겨 다음 세션에도 적용했다.
- 무엇을 묻나: 되돌리기 어렵거나 사용자의 자원·선호가 걸린 갈림길만 묻는다. 회의 피드백 8개 항목에 대해 질문은 4개(디자인 시안 적용 범위, 파일 저장소, 기존 기능 유지 여부, 패키지명까지 바꿀지)였고, 각각 A/B(/C) 선택지에 '(추천)'과 이유를 붙였다.
- 나머지 약 10개는 "질문 없이 이렇게 진행할게 (다르면 말해 줘)"로 가정을 공개했다. 사용자는 4줄로 답했고 그중 2개는 추천과 다른 쪽(이미 가진 계정 활용, 범용성)을 골랐다 — 물은 4개가 실제로 선호가 갈리는 지점이었다. 공개한 가정은 이의 없이 통과했다.
- 사용자 손이 필요한 일(콘솔 설정, 토큰 발급)은 작업을 막지 않게 배치한다: "급하지 않음 — 해당 단계 전까지만, 안 돼 있으면 그 단계를 미루고 나머지부터 진행."
- 자율 범위 밖에 둘 것: 푸시, 공개 저장소 반영, 외부 공유, 기능 제거. 푸시는 매번 확인받았고, 범위 밖 기능을 덜어낼지는 '대체 가능 여부 / 필요성 / 의견' 표로 올려 사용자가 정하게 했다.
- 교정 2: 위험이 낮은 검증(API 키 제한 반영 폴링) 중에 중간 보고가 장황해지자 "그래서 지금 뭐하는거야? … 그냥 넘어가자. 이제 잘거야."가 돌아왔다. 보고는 '지금 하던 일 / 위험도 / 사용자가 할 일(없음)' 3줄로 줄이고, 남은 확인은 백그라운드로 돌린다.
- 작은 작업에도 같다: 디스크 삭제 후보 18개를 '안전 / 확인 필요 / 건드리지 않음'으로 묶어 번호로 내놓자, 사용자가 "1-13번까지 삭제하자" 한 줄로 결정했다.
