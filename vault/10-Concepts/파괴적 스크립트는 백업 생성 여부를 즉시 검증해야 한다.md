## 한 줄 요약

"백업을 만든 뒤 덮어쓴다"고 문서에 적힌 스크립트라도, 실행 환경 문제로 백업 단계가 조용히 실패하고 원본만 파괴될 수 있다 — 파괴적 작업 직후에는 백업 파일이 실제로 존재하고 내용이 있는지 즉시 확인해야 한다.

## 내용

- 실제 사례: Windows Git Bash에서 `python3`가 진짜 파이썬이 아니라 Microsoft Store 설치 안내용 빈 껍데기(스텁)였음. 스크립트는 에러 없이 "실행된 것처럼" 보였지만 백업은 안 만들어지고 원본 파일이 0바이트로 잘려나감.
- 함정의 구조: 도구 문서의 안전장치 설명("원본은 .bak으로 보관됩니다")은 **약속이지 증거가 아니다.** 환경이 다르면 약속은 깨진다.
- 습관화할 검증: 파괴적 스크립트 실행 직후 `ls -la 백업파일` + 크기 확인 (0바이트면 실패). 더 안전하게는 실행 **전에** 수동 백업 한 벌 떠두기.
- Windows 특유 함정: `python`/`python3` 명령이 Store 스텁일 수 있음 — `python --version`이 버전 대신 아무것도 안 찍거나 Store가 열리면 스텁. `py` 런처를 쓰는 게 확실.
