## 한 줄 요약

리프레시 토큰 로테이션(1회용 갱신)을 도입하면 클라이언트의 동시 refresh 호출이 서로의 유효 토큰을 무효화하는 레이스가 생긴다 — refresh 호출은 single-flight(뮤텍스)로 직렬화해야 한다.

## 내용

- 로테이션 구조: refresh 성공 시 기존 리프레시 토큰 폐기 + 새 토큰 발급. 재사용 감지 시 전체 세션 무효화(보안 기능).
- 문제: 클라이언트가 refresh를 동시에 2번 호출하면 (탭 2개, React StrictMode의 이중 mount, 인터셉터 중복 트리거), 첫 호출이 토큰을 회전시키고 두 번째 호출은 "폐기된 토큰 재사용"으로 판정 → 정상 사용자가 로그아웃당함.
- 해결: 클라이언트에서 refresh 요청을 single-flight로 — 진행 중인 refresh Promise가 있으면 새로 쏘지 않고 그 결과를 공유. 서버 측은 짧은 유예 창(grace period)을 두는 변형도 있음.
- React StrictMode는 개발 모드에서 mount를 2번 실행 — 이런 동시성 버그를 조기에 드러내는 역할. StrictMode에서만 터지는 인증 버그는 대부분 실제 레이스다.
