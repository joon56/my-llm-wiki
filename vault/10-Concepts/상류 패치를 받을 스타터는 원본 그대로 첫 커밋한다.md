## 한 줄 요약

나중에 제공자가 패치를 보낼 스타터 키트를 받으면 **고치기 전에 원본 그대로 첫 커밋해 `git apply --3way`가 쓸 base blob을 남기고**, 로컬에서 추가하는 항목 번호는 상류가 이어 쓸 번호대와 분리한다.

## 내용

- 효과: 받은 스타터를 고치기 전에 그대로 첫 커밋해 둔 덕에, 이틀 뒤 온 상류 패치(v1→v3)를 `git apply --3way`로 받을 수 있었다. 이미 여러 문서를 고친 상태였지만 패치는 통째로 실패하지 않고 충돌 표시만 남겼다.
- 원리: 패치의 `index <원본>..<수정본>` 줄이 가리키는 원본 blob이 로컬 객체 DB에 있어야 3-way 병합이 된다. 원본 커밋이 없으면 `--reject`로 적용하고 `.rej` 파일을 손으로 반영하는 수밖에 없다.
- 순서: `unzip -n`으로 풀기(기존 파일 덮어쓰기 금지, 압축 안 경로가 평범한 상대 경로인지 먼저 확인) → `git apply --check`로 시험 → 로컬 변경은 커밋하지 말고 스테이징 → 적용. `--3way`는 `--index`를 함의해서 작업 트리와 인덱스가 같아야 한다.
- 충돌 해결 규칙은 미리 정한다: 로컬이 채운 값·행·메모(측정 사실, 결정 기록, 설정 숫자, 현재 상태)는 보존하고 상류의 새 행·새 키만 더한다. 키트와 다르게 둔 곳(이번엔 4곳)은 이유와 함께 보고해 다음 패치에서 같은 충돌이 반복되지 않게 한다.
- 번호대 충돌: 결정 기록을 상류 번호 뒤(D-27~D-42)에 이어 붙였는데 상류 키트도 같은 범위를 새로 정의해, 로컬 항목을 D-43부터 다시 매기며 문서·설정 주석·코드 주석 127곳을 고치고 겹치는 3건은 합쳤다. 로컬 추가분은 처음부터 별도 접두사나 넉넉히 떨어진 번호대로 시작한다.
- 재번호의 꼬리: 커밋 메시지는 옛 번호를 계속 가리키므로 옛→새 대응표를 변경 기록에 남긴다. 한국어 문서는 받침에 따라 조사가 바뀌어('D-54으로' 같은 오류가 생김) 재번호 뒤 조사까지 검사한다.
- 정리는 검증 통과를 조건으로 건다: 버전 표기, 충돌 표시 0, 번호 연속·중복·없는 번호 참조 0, 설정 파일 로드, CSV 헤더와 문서 일치, 코드 diff가 주석뿐인지, 개인정보 스캔까지 확인했다. 테스트 1건이 실패하자 "다 맞으면 지운다" 조건을 못 채워 패치와 zip 삭제를 보류했고, 커밋은 사용자가 스테이징된 diff를 본 뒤에 했다.
