## 한 줄 요약

제약이 있는 장시간 작업을 시작하기 전에 제약 조건을 명시적인 금지/허용 리스트로 적어 합의해 두면, 에이전트가 수 시간짜리 대형 세션 내내 그 경계 안에서만 정확히 움직인다.

## 내용

- "모델 아키텍처와 손실 함수는 동결, 입력 구성만 자유"처럼 말로 된 제약은 해석 여지가 있다 — 작업 시작 전에 이를 금지 항목 리스트와 허용 항목 리스트로 풀어 쓰고 합의부터 한다.
- 예: 금지 = 레이어 추가/제거, 손실 함수 교체, 옵티마이저 변경 / 허용 = 입력 특징 조합, 전처리, 데이터 구성 변경. 항목이 리스트에 명시되면 판단이 조회로 바뀐다.
- 한 번 합의된 리스트는 수 시간짜리 대형 멀티턴 세션 전체의 불변 기준이 된다 — 중간에 컨텍스트가 길어져도 경계가 흐려지지 않는다.
- 경계 근처의 아이디어가 나오면 에이전트가 임의로 진행하지 않고 "이건 금지 리스트에 걸리는가?"를 먼저 확인하게 되므로, 제약 위반을 사후에 되돌리는 비용이 사라진다.
- 같은 원리가 모호한 지시에도 적용된다: 해석이 A/B로 갈리면 조용히 하나를 고르지 말고 두 해석을 나란히 제시해 선택을 받는다.
- 핵심은 타이밍이다 — 작업 후 교정이 아니라 작업 전 명문화. 리스트 작성 몇 분이 세션 후반의 대규모 재작업을 막는다.
- 무인 작업에는 시간 경계를 더한다. 사용자가 자는 동안 08:00 마감으로 돌린 야간 작업은 시작 전에 규칙을 선언했다: 07:30 새 작업 중단, 07:50까지 검증·보고 완료, `main`에는 통과한 작업만(미완성은 브랜치), 결제가 필요한 서비스와 force push 금지, 사람 손이 필요한 일(터널, 휴대폰 시연)은 범위 밖, 막히면 묻지 말고 기록한 뒤 다음 작업. 실제로 07:29에 끝났고 막힌 항목은 아침 보고로 넘겼다 — 절전 설정 같은 실행 환경 확인도 시작 전 체크에 넣는다.
- 같은 폴더에서 에이전트 둘을 병렬로 돌릴 때도 경계를 작업 전에 정한다: 에이전트별 하위 폴더, 공용 입력 파일 목록, 일일 제출 한도 분담. 도중에 "내 파일은 하위 폴더로"라는 지시를 받아 옮기려 하자, 상대 에이전트의 지침 파일이 옮길 경로(`.venv` 등)를 참조하고 있었고 IDE의 git 감시자가 `.git`을 잡고 있어 rename이 실패했다(복사 후 삭제로 우회). 서브에이전트에도 같은 원리가 통한다 — [[병렬 서브에이전트는 파일 소유권으로 나누고 빌드는 메인이 독점한다]].
- 상시 기록 규칙에도 금지 리스트가 필요하다. "새 사실은 바로 지식베이스에 반영"이라는 규칙만 있자 에이전트가 대화 중 나온 사람 평가·인사 고민까지 공유 문서에 적고 사후에 알렸다. 사람·인사 관련 내용은 '확인 후 기록'이라는 예외를 규칙에 미리 적어 둔다.
