## 한 줄 요약

캐시와 임시 파일을 지워 얻은 용량은 몇 주 안에 되돌아온다. **재발을 끊으려면 성장원(작업 폴더의 tmp, 캐시, 에이전트 산출물)을 측정하고, 그 생성 위치를 영구 설정으로 시스템 드라이브 밖에 옮긴다.**

## 내용

- 타임라인: 캐시·Temp·conda 정리로 C: 여유를 12.7GB에서 29.7GB로 늘렸다. 11일 뒤 약 15.8GB였고, SDK·Gradle 캐시·AVD를 다른 드라이브로 옮겨 19.0GB가 됐지만, 다시 7일 뒤 0.8GB였다 — 삭제로 얻은 17GB가 3주를 못 버텼다.
- 다시 쌓인 것(실측): Temp는 3.3GB 삭제분이 6GB로, npm 캐시는 2.5GB 삭제분이 2.25GB로, 에디터 확장 설치 파일 캐시는 0.59GB에서 1.2GB로, GPU 셰이더 캐시는 약 2GB에서 1.3GB로 돌아왔다.
- 가장 큰 성장원은 캐시가 아니었다: 한 작업 폴더의 tmp(실험용 가상환경·pip 캐시)가 22.6GB였고, 다른 에이전트 세션의 scratchpad에 남은 테스트 임시 파일이 2.3GB였다. 정리 대상 목록만 되풀이하면 이런 성장원은 보이지 않는다.
- 대조군: 환경변수(`ANDROID_HOME`, `GRADLE_USER_HOME`, `ANDROID_AVD_HOME`)로 위치를 옮긴 SDK·Gradle 캐시·AVD는 C:에 다시 쌓이지 않았다. 반면 일회성 플래그(`npm install --cache …`)로만 옮긴 npm 캐시는 기본 경로에 다시 쌓였다.
- 처방은 위치 변경이다: `npm config set cache <다른 드라이브 경로> --location=user`처럼 영구 설정을 쓰고, 큰 도구 폴더(에디터 확장, 다른 도구의 런타임 캐시)는 옮긴 뒤 junction을 건다. 큰 프로젝트는 ASCII 경로의 작업 드라이브로 옮기고, 삭제는 Temp에만 쓴다.
- 측정 순서: 사용자 프로필 최상위 폴더를 크기순으로 정렬하고, 상위 항목을 tmp·.git·.venv 같은 하위 단위로 쪼갠다. 항목마다 삭제 / 이전 / 유지를 정해 효과 큰 순으로 표를 만든다.
- 무엇을 지워도 되는지는 재생성 가능성으로 가른다([[디스크 정리는 이름이 아니라 재생성 가능성으로 분류한다]]). 여기에 더할 규칙은 '지금 쓰는 것'을 피하는 것이다: 실행 중인 프로세스가 쥔 것(MCP 서버가 쓰는 `npm-cache\_npx`, 열린 브라우저의 캐시)은 건너뛰어 목록에 남기고, 동시에 도는 에이전트 세션의 Temp는 3일 이상 안 쓴 대용량 파일만 지운다.
