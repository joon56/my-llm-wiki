## 한 줄 요약

그날 처음 배운 개념을 빈칸 코드로 바로 쓰게 하면 **한 명이 막히는 순간 이후 단계가 전부 무너진다** — 진행자가 기본형을 시연하고, 학생은 같은 패턴을 다른 대상에 반복하며 개념 하나만 더 얹게 하고, 모든 중간 상태가 실행되며 밀린 사람이 다시 따라붙을 지점을 둔다.

## 내용

- 초안의 실패 가정: 입문자가 TODO 4개(생성자 → 객체 → 상속 → 다형성)를 모두 직접 채우는 23분 실습이었다. 사용자가 "배우지 않은 내용으로 코드를 짜기는 힘들 것"이라고 지적했다 — TODO 1에서 막힌 학생은 뒤 TODO를 시작도 못 한다.
- 목표 전환: '직접 짜기'에서 '따라 하고, 바꿔 보고, 결과 보기'로. 빈칸은 줄 단위가 아니라 단어 단위(`extends`·`super`·`@Override` 자리)로, 새 클래스는 기존 예시 파일을 복사해 세 군데만 바꾸게, 힌트는 2단계(비유 → 거의 정답인 코드)로 둔다.
- 쌍 구조(사용자 제안): TODO를 둘씩 묶어 둘째가 '첫째와 같은 패턴 + 응용 하나'가 되게 했다. 대상을 영웅 쪽에서 몬스터 쪽으로 바꿔 같은 패턴을 반복하니 분량이 자연스럽게 맞았고(약 6줄/12줄), 둘째의 힌트는 "TODO 1과 같은 패턴" 한 줄이면 됐다. 더하는 개념은 쌍마다 하나다(오버로딩, 다형성).
- 기본형은 진행자가 시연한다: TODO 1·3은 진행자가 화면에서 직접 치고, 학생은 TODO 2·4만 한다. 방금 본 패턴을 바로 다시 쓰는 구조다.
- 결과가 개념의 필요성을 보여 주게 밸런스를 맞춘다: 초안은 전사 혼자면 드래곤에게 지고 상속으로 마법사를 만들면 이기게 했고, 최종본은 전사와 마법사가 아슬아슬하게 이기도록 드래곤 체력을 250에서 180으로 낮췄다. 마무리는 "전투 코드를 한 줄도 안 고쳤는데 드래곤만 다르게 공격한다"(다형성).
- 모든 중간 상태가 실행되게 한다: 빈칸 그대로 실행해도 오류 없이 끝나고("만들어진 캐릭터 수: 0"), 컴파일을 깨는 단어 빈칸은 주석으로 막아 "채우고 주석 해제"하게 한다. 밀린 학생은 중간저장 프로젝트(TODO 1·2 완료본)를 받아 다음 시연부터 다시 합류한다.
- 배포와 대본도 실습 설계다: 코드는 IDE 프로젝트째 zip으로 줘서 Import 한 번에 열리게 한다(새 프로젝트에 붙여넣게 하면 module-info 생성 같은 입문자 함정을 따로 안내해야 한다). 대본에는 할 말·화면 동작·완성 시 보이는 결과·몇 분 뒤 띄울 힌트·조교용 '오류 메시지 → 원인 → 해결' 표·시간이 밀릴 때 뺄 순서를 넣는다.
