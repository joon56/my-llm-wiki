## 한 줄 요약

엉뚱한 언어로 받아 적는 문제를 막으려 출력 시작을 한국어로 고정하자, 모델이 "말소리 없음"을 고를 수 없게 되어 무음과 숨소리에서 문장을 지어냈다 — **출력 강제는 폴백으로만 쓰고, '답이 없어야 하는 입력'은 모델 밖에서 거른다.**

## 내용

- 증상: 첫 실사용 시연에서 음성 인식 모델(Qwen3-ASR 1.7B, llama-server)이 짧은 감탄사를 `嗯。`·`哦。`·`Yeah.`로 받아 적었다. 요청에 언어 지정이 없어 구간마다 언어를 추측한 탓으로, 이 방식에서는 감탄사 48개 중 16개가 한자·가나로 나왔다.
- 1차 수정: assistant 프리필(`language Korean<asr_text>`)로 출력 시작을 한국어로 고정하자 다른 언어 출력이 0/48이 됐다. 이때는 문제가 된 발화 3종의 전후만 비교했다.
- 부작용(6일 뒤, 다른 모델을 비교하다 발견): 무음에서 "그는 그의 아내를 위해.", 숨소리·짧은 잡음에서 "네."를 만들었다 — 무음·잡음 4종 모두에서. 상담 기록에 끼는 "네."는 동의로 읽힐 수 있다. 출력 시작을 고정하면 '빈 출력'이라는 선택지도 함께 사라진다.
- 2차 수정(2단계 질의): 언어는 모델이 먼저 고르게 하고, 한국어면 그대로 쓰고 "말소리 없음"이면 빈칸으로 두며, 다른 언어일 때만 한국어를 강제해 다시 묻는다. 다른 언어 0/48은 유지되고 환각은 4/4→0/4, 정확도는 같았다. 대가는 구간 평균 258→325ms, 재질의는 감탄사 3개 중 1개·일반 문장 0이었다.
- 근본 해법은 모델 밖에 둔다(사용자 교정): 운영에서 외부 음성 API로 바꿀 계획이면 특정 모델용 프롬프트 조정은 곧 버려진다. 무음·잡음은 모델 앞단(브라우저 VAD, 예: 약 2MB의 Silero VAD)에서 걸러야 모델·API를 바꿔도 유지되고, 오디오 길이로 과금하는 API 비용도 준다.
- 거르는 쪽도 합격 기준을 먼저 정한다: 동의를 뜻하는 짧은 "네"는 버리면 안 되므로 기준은 "감탄사 48개 손실 0, 무음·잡음은 전부 차단"이다. 기존 필터는 음량만 봐서 약 -50dBFS의 작은 소리도 0.3초를 넘으면 모델로 보냈다.
- 일반화: 출력 형식·언어·접두사를 강제하는 수정 뒤에는 원래 실패 사례만 다시 보지 말고 '답이 비어야 하는 입력'(무음·빈 입력·무관한 입력)으로 회귀 검사한다. '해당 없음' 칸이 없는 JSON 스키마나 선택지 강제도 같은 위험을 안고 있다.
