## 한 줄 요약

.ipynb를 직접 손으로 편집하지 말고 생성기 스크립트를 단일 원본으로 삼아라 — `make_notebook.py`가 nbformat으로 노트북을 빌드하고, `jupyter nbconvert --execute`가 실행하고, 다시 nbformat으로 출력 셀을 파싱해 검증하면 노트북·코드·출력이 절대 어긋나지 않는다.

## 내용

- ipynb는 JSON 덩어리라 직접 편집이 위험하고(셀 ID, 실행 카운트, 출력 메타데이터), 코드 수정과 출력이 어긋난 "거짓말하는 노트북"이 되기 쉽다.
- 파이프라인: `make_notebook.py`가 nbformat으로 노트북을 프로그래밍 방식으로 빌드 → `jupyter nbconvert --to notebook --execute --inplace`로 전체 실행 → nbformat으로 출력 셀을 파싱해 결과(정확도, 손실 곡선 등)를 확인.
- 모든 변경 요청(예: 에폭 수 조정)은 스크립트를 고친 뒤 재생성 + 재실행으로 처리한다. 노트북을 부분 수정하는 일은 없다.
- 이렇게 하면 노트북 파일, 소스 코드, 실행 출력 세 가지가 항상 같은 버전을 가리킨다 — 드리프트가 구조적으로 불가능해진다.
- 검증까지 자동화되므로 "실행해 보니 결과가 달라졌다"를 사람이 노트북을 열어보기 전에 스크립트가 먼저 잡는다.
- 채택한 접근이 바뀔 때는 설명 문서도 같은 커밋 단위로 동기화해야 한다 — 노트북만 재생성하고 문서를 방치하면 문서가 새로운 드리프트 지점이 된다.
