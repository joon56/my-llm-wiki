## 한 줄 요약

같은 데이터를 여러 형식(md, ics, rss 등)으로 제공해야 할 때, 각 형식을 손으로 따로 관리하면 반드시 어긋난다 — 단일 진실 원본(SSOT) 하나를 두고 나머지는 전부 빌드 스크립트로 자동 생성한다.

## 내용

- 문제 패턴: 일정 데이터를 마크다운 표에도 쓰고, 캘린더(ics)에도 쓰고, RSS에도 쓴다. 수정할 때 세 곳을 다 고쳐야 하는데, 사람은 반드시 한 곳을 빼먹는다. 시간이 지나면 어느 사본이 맞는지조차 모르게 됨.
- 해결 구조:
  1. 원본은 구조화된 파일 하나 (JSON/YAML/CSV) — 여기만 사람이 편집
  2. 파생물(md, ics, rss, html)은 스크립트가 원본에서 생성 — 사람이 직접 수정 금지
  3. 생성을 빌드/커밋 단계에 걸어서 원본 변경 시 파생물이 자동 갱신되게
- 파생물을 손으로 고치고 싶어지는 순간이 설계 실패 신호 — 그 요구를 원본 스키마에 반영해야 함.
- 이 위키의 구조도 같은 원칙: 세션 로그(원본) → 자동 변환 아카이브 → 사이트 빌드.
- 보기 편하려고 손으로 만든 뷰도 사본이다. 줄글 체크리스트를 인터랙티브 웹으로 바꾸자는 제안이 나왔지만, 그 체크리스트는 답을 받을 때마다 고치는 md였다 — 웹은 금방 낡고, 웹에서 체크한 상태는 md로 돌아오지 않아 원본이 둘이 된다(항목이 가장 많이 바뀌는 주라 더 나빴다).
- 가독성 문제는 원본 형식 안에서 푼다: 항목마다 '누구 · 할 일/질문 → 추천' 한 줄, 근거는 `<details>`로 접고(GitHub과 VS Code 미리보기에서 접힘), 맨 위에 '오늘 할 것'을 둔다. 여러 사람이 체크 상태를 공유해야 할 때만 별도 뷰를 만들고, 그때도 이미 쓰는 공유 시트에 탭을 하나 더하는 편이 싸다.
