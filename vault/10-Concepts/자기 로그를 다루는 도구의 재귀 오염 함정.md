## 한 줄 요약

자신의 실행 로그를 원료로 삼는 도구를 그 로그가 쌓이는 환경 안에서 돌리면, "도구를 만드는 작업" 자체가 새 로그로 기록되어 다음 실행 때 다시 빨려 들어온다 — 필터를 명시하지 않으면 자기참조 오염이 조용히 누적된다.

## 내용

- 이 위키가 정확히 그 사례: Claude Code 세션 로그를 위키로 변환하는데, "위키를 만드는 세션"도 로그로 남아 다음 import 때 위키에 들어옴. 위키에 위키 만드는 이야기가 쌓이는 재귀.
- 방치 시 문제: 메타 작업 로그가 실제 지식 로그를 희석하고, 아카이브 크기가 무의미하게 불어나며, 정제 단계에서 "이건 위키 얘기잖아" 분류 비용이 반복 발생.
- 대응 패턴:
  - **소스 필터**: 변환 시 프로젝트/경로 필터로 메타 작업 세션 제외 (`--project` 등)
  - **정제 단계 규칙**: 메타 세션은 교훈 추출 후 바로 `triaged` 처리
  - **분리 실행**: 도구 개발은 로그가 안 쌓이는 별도 환경에서 (가능할 때)
- 일반화: 로그 수집기·모니터링·백업 도구 전반의 고전적 함정 — 수집기가 자기 수집 행위를 수집하는 구조인지 설계 시점에 점검하라.
