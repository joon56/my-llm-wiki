## 한 줄 요약

호스트는 로컬과 CPU 속도·실행 경로·데이터 규모가 달라 **로컬 통과가 원격 통과를 보장하지 않는다** — 시간은 작업 유형별 배율을 곱해 가장 비싼 경로로 재고, 배선은 강제 경로와 0 가중 동일성으로 확인하며, 단판 제출은 실패 방식까지 설계한다.

## 내용

- 실패 경위: CPU 트리 학습이 많은 패키지가 로컬 571초(한도의 63%, 그중 트리 289초)로 통과했지만 호스트에서 시간 초과로 기각됐다. 호스트 CPU가 로컬보다 2~2.6배 느리다는 기록이 이미 있었는데, 최근 제출이 GPU 위주여서 '호스트≈로컬'로 잘못 일반화했다.
- 배율은 자원 유형별로 따로 둔다: GPU 위주 작업에서 얻은 '호스트≈로컬'을 CPU 위주 작업에 쓰면 안 된다. 경량판(트리 적용 하위 점수 3→1개, 교차 분할 5→2)으로 트리 학습 289→74초, 전체 571→334초로 낮췄다.
- 조건부 경로의 시간: 내부 검증이 후보를 '채택'하면 모델을 재학습하는 설계는, 로컬 합성 데이터에선 늘 기각돼 기각 경로 시간만 측정된다. 채택 시 호스트 예상이 한도의 90~104%로, 잘 될수록 시간 초과가 나는 구조였다. 재학습 모델을 2개에서 1개로 줄여 72~79%로 맞추고, 한도 근처 패키지엔 경과 시간 컷오프(한도의 약 78%를 넘으면 재학습 생략)를 넣었다.
- 배선 검증: 새 경로의 가중치를 0으로 두면 출력이 기준과 비트 단위로 같아야 한다(17,856개 벡터 동일, 연결 지점 호출 정확히 1회). 강제 채택 모드로 한 번 더 돌려 채택 경로가 끝까지 도는지 확인한다.
- 최종 조건 예행: 최종 단계의 데이터 규모로 로컬 예행을 돌려 그 단계에서만 나는 오류와 시간(로컬 1,117초 → 배율 적용 시 한도의 40~65%)을 확인한다. 단판 최종 코드 경로는 실패가 무료인 개발 단계에서 먼저 호스트 리허설을 거친다.
- 실패 방식 설계: 최종 단계가 '성공 1회만 인정, 실패는 재시도 가능'이면 오류·시간 초과 때 조용히 기준 모델 출력으로 후퇴하지 말고 실패시킨다 — 조용한 후퇴는 단 한 번의 성공을 열등한 출력으로 써 버린다. 대체본 사슬(본안 → 경량 폴백 → 기준 모델)은 사람이 결과를 보고 고르고, 내부 컷오프 후 기준 출력은 재시도할 시간이 없는 마감 당일 판독용 제출에만 쓴다.
