## 한 줄 요약

LLM API에서 반복되는 프롬프트 앞부분을 캐시해 토큰 비용과 지연 시간을 줄이는 최적화 기법.

## 내용

프롬프트 캐싱(Prompt Caching)은 [[LLM MOC]]에서 다루는 프롬프팅 전략 중 하나로, 같은 시스템 프롬프트나 맥락을 여러 요청에서 반복할 때 특히 유용하다.

### 캐시 작동 원리

- 프롬프트의 접두사(prefix) 부분이 이전 요청과 동일하면 API는 해당 부분을 캐시된 상태에서 재사용한다
- 캐시 히트 조건: 접두사가 정확히 일치하고, 캐시 TTL(Time-To-Live) 내에 있어야 한다
- 캐시된 토큰은 입력 비용의 90% 할인을 받는다 (Anthropic Claude API 기준)

### 최적화 전략

캐시 히트율을 높이려면:
1. **고정 콘텐츠를 앞에 배치**: 시스템 프롬프트, 도구 정의, 예제 등 변하지 않는 부분을 프롬프트 앞에 배치
2. **순서 유지**: 동일한 콘텐츠도 순서가 다르면 캐시 미스 발생
3. **큰 컨텍스트 활용**: 파일 업로드, 긴 컨텍스트 창이 필요한 경우 캐시 효과가 극대화된다
4. **최소 프리픽스 길이 고려**: 캐시 대상 프리픽스는 모델별 최소 길이 요구사항이 있음 (Anthropic 기준 512~4096 토큰 수준) — 짧은 프롬프트는 `cache_control` 마커를 붙여도 조용히 캐시되지 않음

### 코드 예시

`cache_control` 마커를 사용한 캐시 브레이크포인트 예시 — 여기까지의 콘텐츠가 캐시됨:

```python
from anthropic import Anthropic

client = Anthropic()
response = client.messages.create(
    model="claude-opus-5",
    max_tokens=1024,
    system=[
        {
            "type": "text",
            "text": LONG_SYSTEM_PROMPT,  # 고정 부분 (시스템 프롬프트, 수천 토큰)
            "cache_control": {"type": "ephemeral"},  # ← 캐시 브레이크포인트: 여기까지 캐시
        }
    ],
    messages=[{"role": "user", "content": "질문"}],  # 바뀌는 부분은 브레이크포인트 뒤에
)
print(response.usage.cache_read_input_tokens)  # 0이면 캐시 미적중
```
